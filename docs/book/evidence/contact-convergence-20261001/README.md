## Изолированная угловая замена: не переносится в основной код

Одинаковые strict-FP сборки отличаются одной строкой `solveRotationalLock`:

```cpp
// Исходная формула:
m.jlock = n * clampv(dot(oldL - m.rollMass * wRel, n), -limit, limit);
// Проверенный кандидат:
m.jlock = n * clampv(dot(oldL, n) - m.massTwist * dot(wRel, n), -limit, limit);
```

[Прямой вызов скомпилированного блока](angular_lock_probe.cpp) подтвердил
[локальный контрпример](angular-lock-analytic.json). Но динамический A/B
не прошёл критерий переноса:

| Опыт без сна, поздняя средняя T | Исходный код, Дж | Кандидат, Дж |
|---|---:|---:|
| Цепь, 40 подшагов | 1.906e-6 | 6.526e-6 |
| Цепь, 80 подшагов | 2.037e-6 | 3.952e-6 |
| Sandbox, 20 подшагов, slop 0.1 мм | 1.489e-7 | 8.238e-3 |

У цепи нет разрывов, а измеренная глубина остаётся около 0.1 мм, но дрожание
возросло. В Sandbox кандидат даёт поздний путь 72.07 мм вместо 0.191 мм;
штатный тест остаточного движения провален. В итоговой очереди 21/24 тестов
прошли: оба коротких стека, Noether, обе проверки короткой цепи и CCD;
провалились Sandbox, вложенные чаши и хэш бочек.
[Сводка](angular-regression-summary.json), [команды](angular-trial-checks.json).
Это новые последствия изменения Sandbox,
а не прежнее strict-FP расхождение эталонного хэша.

Поэтому кандидат сохранён как воспроизводимый опыт, **не как исправление
рабочего решателя**. Локальный дефект исходной формулы остаётся открытым.
Следующее исследование должно согласовать twist, дополнительный lock,
rolling и перенос их кэша между изменяющимися площадками; данный опыт
не доказывает, какой из этих механизмов вызвал регрессию.

Числа: `angular-chain-{baseline,candidate}.jsonl`,
`angular-sandbox-{baseline,candidate}.jsonl`. Очередь тестов воспроизводит
[run_angular_trial.py](run_angular_trial.py); пути `/tmp` в ней принадлежат
данному сеансу. Для нового опыта нужны две одинаковые копии SDK и одинаковые
флаги сборки, отличающиеся только приведённой строкой. Времена этих запусков
не используются для ранжирования производительности: параллельно шли другие
проверки и сборка редактора.

## Другие контролируемые опыты

- `sandbox-variants.jsonl`: одна настройка за раз, исходные 10 подшагов,
  6 итераций, slop 4 мм; сон включён и выключен.
- `sandbox-geometry.jsonl`: контроль допуска стенки и шага.
- `sandbox-native-candidate.jsonl`: принятая настройка сцены в native сборке.
- `sandbox-before.jsonl`: исходный strict-FP код до вариационного метода
  воспроизводит прежний Sandbox, включая хэш всей записанной траектории.
- `contact-residual*.jsonl`: диагностические проходы при фиксированной
  геометрии; это не повторная интеграция траектории.
- `shock-chain.jsonl`: native A/B shock propagation, 40/80 подшагов,
  одинаковый начальный толчок, сон выключен.

В [sandbox_probe_control.cpp](sandbox_probe_control.cpp) исходные настройки
явно восстановлены после загрузки сцены. Это сохраняет смысл контроля после
изменения пресета; исходный инструмент брал те же значения из прежней сцены.
Пример повторения:

```sh
c++ -std=c++17 -O3 -ffp-contract=off -fno-fast-math -Isrc -I. \
  docs/book/evidence/contact-convergence-20261001/sandbox_probe_control.cpp \
  /tmp/strict-build/librfsamples.a /tmp/strict-build/librfcore.a \
  -pthread -o /tmp/sandbox-control
RF_THREADS=4 /tmp/sandbox-control geometry
```

Для `angular_lock_probe.cpp` и `contact_residual_probe.cpp` используется
GCC `-fno-access-control`, чтобы вызвать внутренние методы без изменения API
SDK. Этот флаг не добавлялся к производственной сборке.

## Ошибки, которые нельзя скрывать

До настройки Sandbox strict-набор имел 3 проваленных теста из 47:
Sandbox, вложенные чаши и куча 50 бочек; отдельно не совпал golden hash.
В [strict-before-failures.xml](strict-before-failures.xml) исходный снимок
повторяет высоту чаш 258.6 мм вместо ожидаемых 249.3 мм, время сна бочек
5.5 с вместо лимита 5 с, хэши бочек и отдельной эталонной сцены.
Настройка Sandbox устранила только её отказ. Проверенные native 187/187
и 47/47 нельзя выдавать за отсутствие этих strict-FP проблем.

## Санитайзеры

Clang 14, ASan/UBSan, strict-FP: все 16 групп очереди
[asan-nopie-checks.json](asan-nopie-checks.json) завершились с кодом 0.
XML показывают фактический состав групп; фильтр `rigid bodies` захватил также
тесты взаимодействия с газом. Это не полный набор всех подсистем.
Сборка предшествовала последнему изменению конфигурации Sandbox; перечисленные
фильтры Sandbox не вызывают.

Первоначальный PIE executable иногда падал до `main` без отчёта санитайзера.
Контроль с пустым `main` воспроизвёл 7 таких падений за 20 запусков;
тот же контроль с `-no-pie` прошёл 20/20. Поэтому только временная Linux-сборка
использовала `-DCMAKE_EXE_LINKER_FLAGS=-no-pie`. CMake проекта не изменён ради
этого обхода. Сохранены оба контрольных JSON и исходник пустого main.
Устранение нестабильного старта среды не является исправлением физики.

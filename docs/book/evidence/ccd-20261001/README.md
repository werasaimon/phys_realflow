# Проверка CCD — 01.10.2026

> Исторический срез до атомарного шага. Его исходники и бинарник отличаются
> от текущего SDK; команды трассировки требуют именно прежних заголовков и библиотек.
> Новая реализация и результаты: [CCD с повторным расчётом](../ccd-retry-20261001/README.md).

Исследуется рабочая версия после `2d0adca`; точные хэши источников и бинарника —
в [verification.json](verification.json). Release, GCC, `RF_WERROR=ON`,
`RF_STRICT_FP=OFF`, два потока, CPU 8/9, nice 15, предел памяти 2 ГиБ.
Это регрессия реализации, не сертификат непересечения и не оригинальный набор Rigid IPC.

обнаружения ошибок балки и сферы у пластины; за завершённые они не выдаются.

## Оставшийся отказ: шаг 1/1200 с

[sensitivity.jsonl](sensitivity.jsonl) содержит шесть прогонов балки и `RigidCcd`
по 2 с с шагами 1/600, 1/1200 и 1/2400 с. При среднем шаге смешанная сцена
переполняет энергию на 22-м подшаге. **Этот дефект пока не исправлен.**
Глубина многообразия не является независимой проверкой геометрического пересечения.
Время диагностического прогона включает копирование тел и не служит бенчмарком.

Воспроизведение из корня SDK:

```sh
c++ -std=c++17 -O3 -march=native -Isrc -I. \
  docs/book/evidence/ccd-20261001/sensitivity.cpp \
  build-core/librfsamples.a build-core/librfcore.a -pthread -o /tmp/ccd-sensitivity
RF_THREADS=2 nice -n 15 taskset -c 8,9 timeout 60s \
  prlimit --as=2147483648 --core=0 -- /tmp/ccd-sensitivity
```

[Трасса ограничения позы](mixed_trace_clamp-output.txt) непосредственно измеряет скачок
вращательной энергии тела 32 с 1706.265 до 4135.717 Дж за одну операцию.
[TimeOfImpactTrace.cpp](TimeOfImpactTrace.cpp) — копия проверенного исходника с
печатью до/после ограничения; в рабочий SDK она не включена. Для повторения:

```sh
c++ -std=c++17 -O3 -march=native -Isrc -I. \
  docs/book/evidence/ccd-20261001/mixed_trace.cpp \
  docs/book/evidence/ccd-20261001/TimeOfImpactTrace.cpp \
  build-core/librfsamples.a build-core/librfcore.a -pthread -o /tmp/ccd-clamp-trace
RF_THREADS=2 /tmp/ccd-clamp-trace
RF_THREADS=2 /tmp/ccd-clamp-trace no-ccd
```

[Контроль без CCD](mixed_trace_no_ccd-output.txt) конечен в течение 60 подшагов; это
диагностическое сравнение, которое не проверяет безопасность столкновений.
[Прежняя трасса балки](beam-traces.json) показывает устранённое геометрическое
зависание; она не опровергает новый контрпример смешанной сцены.

Формулы, источник ошибки и следующий этап согласования полного состояния
описаны в [главе 9](../../09-ccd-contract.md).

## Проверка в редакторе

Редактор собран в `/tmp/phys-realflow-editor-standard-build` с `RF_SDK_DIR`,
указывающим на этот рабочий SDK. Исходники соседнего редактора не менялись.
Снимки проверены визуально; CSV сохранены здесь. Геометрический максимум
нельзя выводить из глубины многообразий, измеренной лишь на опубликованных кадрах.

| Сцена | Потоки | Модельное время | Наибольшая глубина многообразия |
|---|---:|---:|---:|
| [120 торов](editor-tori.csv) | 2 | 0.517 с | 0.327 мм; разрывов нет |
| [Чаша и 60 тел](editor-bowl.csv) | 2 | 2.050 с | 4.806 мм |
| [6 вложенных чашек](editor-cups.csv) | 10 | 6.283 с | 0.400 мм |
| [24 невыпуклых тела](editor-sandbox.csv) | 10 | 2.033 с | 3.972 мм |
| [45 моделей на рельефе](editor-terrain.csv) | 10 | 2.017 с | 0.628 мм |

Все эти короткие запуски сохранили конечность опубликованной энергии.
На чашках зарегистрировано до 1783 контактных точек, на рельефе — до 1224.
Это проверка демонстраций, а не доказательство устойчивости при любом движении мышью.
Запрошенные 120 кадров могут быть превышены: автоматика останавливает симуляцию
при получении очередного снимка GUI. В таблице указано фактически записанное время.

Для интерактивного просмотра:

```sh
RF_THREADS=10 nice -n 10 taskset -c 1-5,7-11 \
  /tmp/phys-realflow-editor-standard-build/realflow --preset 35
```

Номера: 35 — чашки, 38 — смешанная куча, 36 — рельеф, 39 — 120 торов.
На проверенной машине 6 физических ядер / 12 логических процессоров; привязка
оставляет ядро с процессорами 0/6 системе. Номера CPU для другой машины нужно
подбирать заново. Число потоков не означает постоянную загрузку всех ядер:
зависимые контакты решаются последовательно, независимые — параллельно.

Текстовые журналы сохранены как `*-output.txt`; числа и сообщения исходных логов сохранены; в общем отчёте удалены пробелы в конце строк.
